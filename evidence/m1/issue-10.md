## Native command envelope and outcomes

The [manual runbook](../../docs/m1-identities-native.md) gives the full Docker wrapper and secret handling. For every row below, the locked tools image ran as the host UID/GID on only the relevant `supply-<org>` internal network with `--read-only --tmpfs /tmp`. A read-only mount exposed only the corresponding `.runtime/trust/<org>-tls-ca.pem` (or `orderer-admin-tls-ca.pem`) at `/trust/ca.pem`. Registration additionally mounted only the correct CA registrar MSP read-only at `/registrar`; enrollment mounted only that identity's writable directory at `/identity`. The matching 0600 secret was mounted read-only at `/run/secrets/enroll` (or `/run/secrets/bootstrap` for registrar enroll) and read inside the container. Every invocation specified `--home`, `--mspdir`, `--tls.certfiles /trust/ca.pem`, exact HTTPS `--url`, and `--caname`. Each new identity had its own secret and output directory; no shell loop or batch script performed native issuance.

The common Docker wrapper and secret expansion are omitted **only from the table cells** to keep each concrete native command readable. `<redacted>` is an actual private file's value, not a missing option. Each listed result was checked from its own ignored native output log immediately after execution. All 58 client commands exited 0; there was no failed CA native command. A host-only metadata probe using `openssl x509 -ext subjectAltName` failed because the available host OpenSSL variant did not support that option; it was replaced by read-only `openssl x509 -text -noout` parsing, which passed. That diagnostic failure neither registered nor enrolled an identity.
