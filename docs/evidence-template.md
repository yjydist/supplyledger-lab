# 阶段证据模板

本文件是填写模板，不是已执行测试的报告。复制到 `evidence/<milestone>/<test-or-issue>.md` 后，按实际运行结果替换尖括号内容。结果只用 `PASS`、`FAIL`、`NOT RUN`；缺少执行证据时写 `NOT RUN` 和原因。网络、交易或性能尚不存在时保留 `NOT RUN`，不能填推测值。

## 证据封套

- 测试编号：`<§20 ID 或本阶段稳定 ID>`
- 对应规格：`<章节、CON/INV/ADR 编号>`
- 源码 commit：`<被测代码完整 SHA；若报告与代码同次提交，提交后以本报告路径解析完整 SHA>`
- 版本锁：`<versions.lock.yaml 的 SHA-256 与使用的平台；若未建立，NOT RUN — 原因>`
- Compose 档位：`<bootstrap/dev/resilience 等实际档位；未使用时 NOT RUN — 原因>`
- 网络身份：`<channelId、实际 genesisHash；未建通道时 NOT RUN — 原因>`
- 准备数据：`<脱敏列出实际准备的镜像、临时卷、CA/通道产物、测试身份、fixture、业务对象 ID 与前置状态；没有则写 none>`
- 环境：`<宿主机架构、容器平台、关键镜像完整引用和资源条件>`
- 脱敏规则：`<已删除的密钥、口令、token、私有条款、路径；确认公开输出不含原值>`

业务链上前置状态必须通过正式业务交易生成，不得直接修改 CouchDB 或 PostgreSQL 来伪造业务 fixture。

## 操作与判定

| 测试编号 | 实际命令或可复现入口 | 预期结果 | 实际结果及原始证据位置 | 判定 |
| --- | --- | --- | --- | --- |
| `<ID>` | `<命令、参数、环境中非秘密部分>` | `<可观察结果>` | `<退出码、输出摘要、区块/日志路径；未运行则写 NOT RUN — 原因>` | `NOT RUN` |

交易存在时逐笔补充 txId、区块高度、validation code、提交状态与来源 Peer；没有入块的失败只记录发生阶段及脱敏日志，不编造交易编号。超时与未知结果记录全部 attempt txId 和后续收敛，不把 `SUBMITTED`、`PENDING_UNKNOWN`、`COMMITTED_VALID` 混写。故障实验记录注入与恢复动作；性能实验记录 offered load、有效提交、无效和未知数、延迟分位数及宿主/容器资源。截图仅作辅助，判定应能由命令、区块或自动化断言复核。
