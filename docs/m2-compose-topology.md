# M2 base Compose topology

This is the static Compose portion of [issue #15](https://github.com/yjydist/supplyledger-lab/issues/15), implementing `SPEC.md` §§3.1–3.5 and `CON-08` on the M1 CA baseline. The overlay is [compose/network.yaml](../compose/network.yaml). It declares three Orderers, one Peer and one CouchDB for each founding business organization. These nine services have no profile. The nine CAs retain the `ca` profile from [compose/ca.yaml](../compose/ca.yaml); the M0 tools service retains its `bootstrap` profile.

| Service group | Network membership | State | Host port |
| --- | --- | --- | --- |
| `orderer0`–`orderer2` | `supply-fabric` and internal `supply-orderer` | One ledger volume per Orderer | None; gRPC 7050 and admin 9443 stay in Docker networks |
| `peer0-seller`, `peer0-buyer`, `peer0-carrier` | `supply-fabric` and only their own internal organization network | One ledger volume per Peer | None; gRPC/Gateway 7051 stays in Docker networks |
| `couchdb0-seller`, `couchdb0-buyer`, `couchdb0-carrier` | Only their own internal organization network | One data volume per CouchDB | None; 5984 stays in Docker networks |
| Nine M1 CAs | Only their respective internal organization network | Nine existing, separate CA volumes | None; 7054 stays in Docker networks |

The declared DNS aliases use the exact service hostnames in `SPEC.md` §3.3 and the M1 [TLS trust matrix](m1-tls-trust.md), for example `peer0.seller.supply.test` and `orderer0.orderer.supply.test`. The Fabric network is shared for Peer/Orderer traffic; the four organization networks are `internal: true`. The current base services publish no host port. Future organization APIs must use the §3.4 loopback mapping `127.0.0.1:8081`, `:8082`, `:8083` and later Audit `:8084`; they are not declared in this M2 overlay. Network isolation limits ordinary containers; a host Docker administrator can still inspect or cross these boundaries, as in ADR-004.

Each node has its own `/var/hyperledger/production` named volume. Each CouchDB has its own `/opt/couchdb/data` named volume. Peer and Orderer root filesystems are read-only with a `/tmp` tmpfs; they mount their own local MSP and TLS material, their service configuration, and the public roots needed for their role. M2 #16 additionally mounts the same public, repository-owned deny-all builder directory read-only into each Peer; it contains no identity or secret and rejects every chaincode package until M3 #22 replaces it. Bind sources use `create_host_path: false`, so missing configuration, builder or identity material fails before a node starts instead of creating empty directories. No service mounts `docker.sock`. All images use the measured references in [versions.lock.yaml](../versions.lock.yaml) with exact digests and `pull_policy: never`.

M2 [#16](https://github.com/yjydist/supplyledger-lab/issues/16) authors the three `network/config/ordererN.yaml` and three `network/config/peer0-<org>.yaml` source templates. Its [node runbook](m2-node-config-native.md) renders their deployment-specific private key paths into ignored `.runtime/network-config/` files mounted here. It creates per-organization ignored `.secrets/couchdb/<org>.env` containing `COUCHDB_USER` and `COUCHDB_PASSWORD`, and matching `.secrets/peer-couchdb/<org>.env` files containing only the corresponding Fabric Peer CouchDB environment keys. Passwords are absent from committed Compose and verification output. The env files are optional to Compose parsing so `make network-config` can run before node preparation; the pinned CouchDB image refuses startup without an admin account. #16 must inspect the **running** containers, including mounts, published ports and separate volumes, to complete full `T-NET-02`. It must not claim a static model is a live result.

M3 [#22](https://github.com/yjydist/supplyledger-lab/issues/22) must add `cc0-seller`, `cc0-buyer` and `cc0-carrier` as no-profile services in this base topology, each on only its organization's internal network and with its own state/configuration as required by `SPEC.md` §§3.1, 3.3 and 3.5. It must replace the temporary pinned official Peer image and M2 deny-all builder bind with the repository-built, digest-pinned external-builder image and configure Peer→CCaaS mTLS with distinct per-Peer client credentials. No runnable CCaaS image or server credential exists in M2, so CCaaS startup and handshake results remain **NOT RUN** here. The requirement is tracked in #22, not waived.

## Static check and lifecycle

Run `make network-config` from the repository root. It merges the bootstrap, CA and network overlays with `--no-env-resolution`; this checks syntax without reading CouchDB password values. The [policy checker](../scripts/verify-m2-compose.py) checks the exact current service and network sets, no host ports or Docker socket mounts, locked images, exact DNS/network membership, named state volume separation, read-only identity and deny-all builder mounts, the builder's exact files/modes/hashes, a narrow Peer/Orderer environment allowlist and reset allowlist labels. `make test-m2-compose` exercises the checker against unsafe mutations in a temporary Compose copy. A **PASS** covers the rendered Compose model and tracked builder files only. Full `T-NET-02` also needs the later live Docker inspect and repository secret review. Do not print full `docker compose config` or `docker inspect` output into evidence after private env files exist; those outputs may contain passwords.

`make stop` and `make down` use all three current overlays and retain named volumes. `make reset` requires `CONFIRM_DESTROY=supplyledger`, prints the exact **existing** reset-enabled Compose volumes and leaves backups/external volumes alone. An unconfirmed `make reset` can be used to review the deletion list; it exits 2 without deleting project data. A declared new M2 volume does not appear in that list until a real node/database creates it. Network startup, channel genesis and first join commands remain separate native M2 steps, not part of `make network-config`.
